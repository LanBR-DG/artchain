# 法律协议文件说明（运营方必读）

四份协议位于 `artchain/web/legal/`，与应用同款式（浅色/深色自适应），
在应用内通过 `/legal/*.html` 访问，并已接入登录门勾选与**服务端同意留痕**：

| 文件 | 内容 | 访问路径 |
|---|---|---|
| `terms.html` | 用户服务协议 | `/legal/terms.html` |
| `privacy.html` | 隐私政策（PIPL 结构） | `/legal/privacy.html` |
| `points.html` | 平台积分规则（合规定性核心） | `/legal/points.html` |
| `community.html` | 社区规范（链上不可删除告知） | `/legal/community.html` |

## 一、上线前必须替换的占位符（全文搜索【）

- 【运营方名称 / 公司名称】：实际运营主体（须与备案主体一致）
- 【注册地址】【联系方式 / 客服邮箱 / 投诉邮箱 / 个人信息保护负责人邮箱】
- 【ICP 备案号】【公安备案号】【区块链信息服务备案编号】（三样都要真实存在）
- 【2026-__-__】生效日期

替换后在 `artchain/api.py` 的 `LEGAL_DOC_VERSIONS` 里递增对应文档版本
（例如 `"terms": "1.1"`），老用户的同意记录会与新版本对比，再次登录时
重新要求勾选——这是「版本留痕」的机制，不要跳过。

## 二、已经替你挡掉的风险（协议中的关键条款）

1. **积分定性（最高风险）**：`points.html` 第一条明确积分是「生态内单用途
   虚拟积分」，不是货币/法币电子形式/证券/金融产品，不承诺任何收益，
   **不得兑换法币、不得提现、不得平台外转让或变现**，并援引银发〔2021〕237 号
   通知划清与虚拟货币的界限。
2. **链上不可删除**：`terms.html` 第 4.3、10.2 条与 `privacy.html` 第三条、
   `community.html` 第二条，三处反复告知「上链即永久、不可删除、发布前确认」，
   侵权投诉只能做「隐藏展示」——这是区块链产品的核心免责前提。
3. **存证 ≠ 版权登记**：`terms.html` 第四条明确链上存证只证明「什么内容、
   何时、由谁固定」，不审查独创性与权属，不承诺诉讼结果。
4. **口令不可找回**：`terms.html` 第 5.2 条明确运营方不保管、无法找回口令。
5. **告知同意的证据**：登录门勾选 + 服务端 `consents.json` 留痕（钱包、
   时间戳、文档版本），重复解锁幂等不刷屏。

## 三、上线前的法务检查清单（务必逐项过律师）

- [ ] 运营主体名称、资质、注册地址与协议一致
- [ ] 完成三项备案/登记：ICP 备案、公安联网备案、**区块链信息服务备案（网信办）**；
      积分功能上线前按业务形态评估是否需要增值电信业务许可（如涉及经营性服务）
- [ ] 律师确认积分条款的定性（若未来开放兑换商品/权益，需复核是否触发
      单用途预付卡、电子商务等其他监管规则）
- [ ] 律师确认「链上不可删除」条款与《个人信息保护法》删除权的平衡表述
- [ ] 律师确认社区内容审核机制（《网络信息内容生态治理规定》要求的
      处置措施、举报渠道、保存记录）
- [ ] 未成年人保护条款与「青少年模式」是否满足监管要求（若面向未成年人）
- [ ] 隐私政策与实际数据流一致（尤其是：明文口令不过服务器、
      链下原件存储位置、日志内容）
- [ ] 明确服务器部署地域与数据出境情况（隐私政策已默认「境内存储」，
      若实际部署在境外必须改）

## 四、微信小程序特别注意

小程序审核要求独立的「用户隐私保护指引」配置（小程序后台 → 设置 →
服务内容声明 → 用户隐私保护指引），需与上述隐私政策保持一致；
注册/首次使用流程中同样要弹窗展示协议并留痕。上线前在小程序
后台完成该项配置，并把四份协议的链接换成线上可访问的 HTTPS 地址。
